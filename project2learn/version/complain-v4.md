# Project2Learn v4 版本说明

## 第四版要解决什么

v3 已经建立 `Touch → Understand → Own`、技术地图、学习模式和直接实践证据。但输出仍容易把课程设计模型原样摊给学习者：一篇 milestone 同时展示当前版本、因果字段、能力、AI 边界、验收、证据和风险。它结构完整，却更像课程设计文档或 AI 分析报告，不像正在陪学习者做项目的教材。

v4 的核心原则是：

> 不要把因果链告诉学习者，要让学习者经历因果链。

因此新增明确的 `Learning Experience Renderer / 学习体验渲染器`，把系统拆成两层：

```text
仓库分析 → 能力模型 → 学习者差距 → 因果单元模型
                         课程设计层
                              ↓
                    学习体验渲染器
                              ↓
                         学习者教材层
```

## 方法来源与改造边界

本版继续吸收李勃老师公开课程中的原则：在“做”中理解、先触摸再理解、明确且负责任地说“现在不讲”、设置步骤级目标并让每一步拿到结果：

- https://李勃老师.com/
- https://李勃老师.com/zero-to-fullstack/lessons/module-6-5/

SQLite 课件先让学习者检查 `main.py` 中散落的存储职责，再说明为什么此时只拆存储层，并明确“不要为了重构而重构”。Project2Learn 只吸收这种问题先出现、抽象后命名、按压力增加复杂度的表达机制；不复制具体技术栈、课程内容或固定步骤。

## v4 的八项改进

### 1. 课程设计层与教材层分离

密集的因果链、能力、证据、AI 边界、验收、提示、源码桥接和延迟概念进入语言中立的 `course/design/` JSON。`project-evolution.md`、`knowledge-graph.md` 和 `architecture.md` 继续存在，但被明确标记为参考材料，不再是开课前的主要阅读路径。

### 2. milestone 与 foundation 改为 lesson bundle

新课程不再用一篇密集 Markdown 承担整个单元。每个 foundation 包含 1–3 课，每个 milestone 包含 2–5 课：

```text
course/design/milestones/03-persistence.json
course/zh-CN/milestones/03-persistence/01.md
course/zh-CN/milestones/03-persistence/02.md
course/en/milestones/03-persistence/01.md
course/en/milestones/03-persistence/02.md
```

拆分依据是学习者正在完成的动作和结果，不是 API 名称。

### 3. 一课一个认知目标

每课只能围绕一个认知变化：看到一个现象、理解一个必要概念，或把一个概念接回项目。若一课同时承担多个无关概念，必须拆分。

### 4. 从“解释因果”改为“经历因果”

内部仍保存：

```text
previous_value → new_problem → concept → resolution → next_pressure
```

教材渲染为：

```text
先做 → 看到现象 → 停下来问 → 尝试最小方案 → 给概念命名
→ 只讲当前所需 → 用回项目 → 看见作品成长 → 遇到下一个问题
```

### 5. 正式支持“现在先不讲”

每课最多一个可选的“现在先不讲 / Not Now”段落，必须同时说明现在为什么不需要、未来什么压力出现时会回来。它不能用来推迟当前阶段必要的安全、数据保护或信任边界处理。

### 6. AI 边界改写成自然辅导语言

精确责任边界仍保存在 design JSON 和进度证据中。教材不再反复展示合同式的 `AI 可以 / 学习者必须` 表格，而是在关键动作旁自然说明为什么这一小段值得亲手完成、卡住时怎样先让 AI 给提示。

### 7. 每课显示作品进度

结尾必须回答“现在你的项目可以做什么”，而不是罗列学过的术语；再用一个自然问题推动下一课。

### 8. schema v4 记录当前 lesson

新工作区使用 schema v4，在 `current_unit` 之外增加 `current_lesson`。旧 schema-v1/v2/v3 继续按原结构验证和恢复，不重置历史进度。

## v4 不做什么

- 不删除底层能力 DAG、证据台账或因果模型；只把复杂度藏到设计层；
- 不强制每课使用相同篇幅；
- 不按函数或 API 清单机械拆课；
- 不用“轻教材”替代精确验收和学习者实践证据；
- 不把 `architecture.md` 等参考文档伪装成学生必读正文；
- 不因追求故事感而隐藏当前结果所需的错误处理、安全或数据保护。

## 最终判断标准

生成每一课后只问一句：

> 这一页是在告诉我课程怎么设计，还是让我正在做一个东西？

v4 要让复杂设计留在底层，让学习者表面的体验变成：每当项目刚好需要一个知识时，旁边的人只讲足够继续做下去的那一点。
