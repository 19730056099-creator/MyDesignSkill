# Project2Learn v3 版本说明

## 第三版要解决什么

v2 已经解决了“为什么这个阶段现在出现”：课程以项目压力而不是目录或知识树组织，并用因果链连接前一版本、新问题、设计变化和下一项限制。

但学习者仍可能遇到四个问题：

1. 知道当前要实现什么，却不知道命令、进程、网络、应用和存储分别位于哪一层；
2. 先读完解释再操作，缺少形成直觉的第一次真实接触；
3. AI 生成了可运行代码，但学习者没有完成关键操作、解释、调试和迁移；
4. 能力只被标记为“会/不会”，没有体现从接触到迁移的理解深度。

v3 的核心原则是：

> 沿产品生长路线，在问题出现时引入知识；先通过操作建立技术地图和直觉，再解释原理；AI 降低机械实现成本，学习者承担关键实践、理解与结果责任。

简称：

```text
Touch → Understand → Own
触摸 → 理解 → 承担
```

## 方法来源与改造边界

该方向吸收了李勃老师公开课程设计文章中的学习路径思想：从结果倒推、先场景和最小结果、再解释原理、最后增加复杂度，并让实践服务明确的能力目标。参考：

- https://李勃老师.com/blog/how-to-design-a-good-tech-course/
- https://李勃老师.com/zero-to-fullstack/lessons/module-1-2/
- https://李勃老师.com/zero-to-fullstack/lessons/module-1-1/

Project2Learn 不绑定 React、FastAPI、SQLite 等具体技术栈，也不把任何课程顺序当作通用模板。它把这些思想转换成仓库证据驱动、双语同步、可校验的通用课程契约。

“AI 负责 80% 机械编码、学习者负责 100% 理解和关键 20%”只是一种直觉，不是机器验收比例。不同项目和学习目标必须逐单元声明责任边界。

## v3 的六项改进

### 1. 学习模式

准备度之外增加：

- `product_builder`：优先完整产品和工程地图，允许 AI 生成更多脚手架；
- `cs_depth`：在项目真实使用的控制流、协议、数据结构、并发、内存或系统边界上增加亲手实现；
- `balanced`：AI 降低机械成本，学习者完成关键操作/代码、解释和代表性故障诊断。

模式来自学习者明确目标；不根据专业、年级或表达自信程度猜测。

### 2. 技术层级与故障定位地图

`project-map.md` 新增：

- 技术层级地图：用户动作、命令/客户端、进程或网络边界、应用组件、存储；
- 故障定位地图：可观察故障、可能层级、第一检查动作、下一条边界。

地图只覆盖选定项目路径，不扩展成完整 Linux、网络或运维课程。

### 3. 每个单元采用 Touch → Understand → Own

foundation 和 milestone 新增：

- `First Touch / 首次触摸`：场景、最小动作、立即可观察结果；
- `AI Usage Boundary / AI 使用边界`：AI 可生成、学习者必须亲手完成、必须解释的内容；
- `Understanding and Transfer Check / 理解与迁移检查`：改变一个条件后解释、调试或迁移。

理论不被删除，而是在学习者获得最小直觉后出现。

### 4. 螺旋式实践深度

能力实践深度使用：

```text
unseen → touched → explained → debugged → transferred
```

不是每个能力都必须达到 `transferred`。路线只安排项目目标真正需要的深度，并在后续单元自然复现，而不是重复讲同一节课。

### 5. 直接实践与 AI 使用证据

schema v3 增加 `practice_evidence`。通过的单元记录：

- `unit_id`；
- 达到的 `depth`；
- 学习者的 `manual_action`；
- `observable_result`；
- 学习者的 `explanation`；
- `ai_usage`；
- `timestamp`。

可运行输出仍是必要证据，但不再单独等价于掌握。

### 6. 更强的结构校验

v3 校验器新增：

- 新工作区使用 schema v3；
- active 课程必须完成学习模式决策；
- v3 项目地图、readiness、知识图谱和单元必须包含新增章节；
- `GETTING_STARTED.md` 必须使用完整双语标题和 `language: bilingual`；
- passed 单元必须有匹配的直接实践证据；
- 课程状态与单元状态使用不同集合；
- foundation 和 milestone 文件编号必须从 1 连续且使用两位数字。

schema-v1/v2 工作区继续兼容。迁移只影响未来未开始单元，不重置进度，也不伪造历史实践。

## v3 不做什么

- 不要求所有代码手写；
- 不把固定手写比例当作学习质量；
- 不把 foundation 扩展成完整通识课程；
- 不为了“先触摸”而省略安全、数据保护或必要错误处理；
- 不把教学演变路线声称为作者真实历史；
- 不让 AI 使用方式取代行为验收、源码证据或学习者解释。

## 最终结果

v1 回答“学什么、如何验证”；v2 回答“为什么现在学”；v3 继续回答：

```text
第一次如何接触？
它在整个系统哪一层？
AI 可以帮到哪里？
学习者必须亲手承担什么？
如何证明不只是运行了生成代码？
这个能力以后如何以更深层次再次出现？
```
