# Project2Learn v1 版本说明

## Skill 设计目的

Project2Learn v1 的目标，是把一个成熟代码仓库转换成一门可以“从零重建”的中英双语项目课程，而不是只解释最终源码。

它希望学习者通过亲手实现一组可运行的阶段，逐步获得理解成熟项目所需的语言、工具、框架、领域知识和工程能力。

## 要解决的问题

成熟仓库通常只展示最终形态，学习者容易遇到以下困难：

1. **最终代码信息密度过高**：入口、业务逻辑、数据层、错误处理和工程机制同时出现，不适合直接模仿。
2. **源码讲解不等于学习路线**：按目录或文件解释代码，不能告诉学习者应该先实现什么、后实现什么。
3. **项目要求不等于学习者已经掌握**：课程若默认学习者会 Git、语言、框架或领域知识，第一步就可能无法开始。
4. **通用前置课程过宽**：让学习者先完成整门语言或框架课程，会补充大量当前项目不需要的内容。
5. **缺少可验证的学习闭环**：只有说明文档，没有阶段验收、渐进提示、实现评审和跨会话状态，学习过程容易中断。
6. **仓库事实与教学推断容易混淆**：从最终代码推测设计动机时，容易把合理解释误写成作者真实历史。

## v1 的核心方案

- 参考仓库只读，课程和学生代码写入独立工作区；
- 建立语言中立的仓库模型和项目所需能力 DAG；
- 通过自评或微诊断确定学习者起点；
- 只为个人缺口生成短小的前置补给单元；
- 倒推成熟能力，再正向排列 5–12 个可运行里程碑；
- 同步生成 `zh-CN` 和 `en` 课程；
- 区分 `code_evidence`、`document_evidence`、`teaching_inference` 和学习者证据；
- 提供五级提示、阶段感知评审和 `progress.json` 状态机；
- 用校验器检查双语结构、ID、来源、命令、验收和状态一致性。

## v1 的边界

v1 已能回答“学什么、按什么顺序做、如何验证”，但对“为什么当前阶段必然从上一阶段长出来”的表达仍不够稳定。这个缺口成为 v2 的主要改进目标。
